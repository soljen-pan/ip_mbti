## 0. 可直接复制给本地 Agent 的任务

你要**在现有「入戏档案」微信小程序项目中完成整套玩家端 UI 美化，并形成商家工作台的配套 UI**。先读取项目结构、页面路由、组件、现有资源，再读取项目使用的《ru-xi-player-personality-miniapp-spec-v1.md》最新 v2.2 版本。以本包 `reference/approved-direction-preview.png` 为**用户已接受的视觉方向**，以此 Markdown 为逐页规格，以原产品文档为人格、题库、配对、主题和预约的业务真值。检查并沿用现有正式角色资产及授权接口。没有源代码或正式角色资产时，先做能落地的页面设计稿与资产槽定义，不伪称已经完成接入。

**核心方向：**让已提供的夸张小孩鬼 NPC 角色图成为产品视觉主角。角色具有粗黑漫画墨线、蓝灰色统一露肤、夸张表情、散乱头发、破紫色戏服、NPC 工牌和故事道具。界面围绕它使用清爽暖白底、黑色手绘短线和对话气泡、薄荷绿／淡紫记号笔刷、少量高饱和紫按钮。需要有密室探索的代入感，但整体属于**轻喜剧漫画密室**，不是写实恐怖片，也不是复古金边剧场。上一版暗色写实舞台背景已被用户否决，不要引用旧包中的 `home-theatre.png`、`question-paper.png` 或 `result-stage.png`。

### 不可违反的产品规则

- 基础题 **60 题**：B001—B056＋E001—E004；特定答案触发 H001—H040 分支，单次最多 **100 题**。开始页和问卷进度写明 60＋条件补问；不要所有用户都写成必做 100。允许保存、继续、改答。`无法判断` 是独立未知值，不是中位数。
- 人格代码前四位共 16 种主角色，第五位 K/R 为运动参与姿态；如 `ADVC-K · 故事漫游者`。与胆量反应分类 `巨坦 T-G／微坦 T-M／尖叫奶 N-S／哑巴奶 N-Q` **分层展示**。坦与奶互斥，信息不全显示“坦奶待补答”。K 不等于能接受 NPC 追逐，R 不等于胆小。
- 剧情共鸣与落泪倾向是两个独立文字标签；六星图依次为入戏投入、互动意愿、探索欲望、刺激偏好、动能偏好、协作意愿。未知维度留空并有文字说明，不补零。
- 配对须区分静态类型参考、双方授权的真实双人及具体队伍／主题／场次。坦奶互补可提示，但不是保证；双奶自嘲“门口礼让三百回合：您先，您先”须带低恐、陪同建议。个人明确拒绝优先于软评分；未知表示待确认，不能猜为安全。
- 主题玩法、必做追逐／贴脸／黑暗／声音／单人任务、路线、陪同和资格必须有商家核实的来源与版本。商家识别结果是草稿；没有真实接入时演示主题标“演示数据”，不伪造门店、库存、价格。申请、商家审核、留位报价、玩家确认、最终预约确认与支付是不同状态。
- 正式角色由用户提供，**不要生成新的 16 类人物插画**。用户真实年龄不决定儿童漫画外观，漫画男女童／可选中性换装不改人格和配对。所有角色裸露的面、耳、脖、手臂／手、腿保持同一种异常蓝灰皮肤。不要从预览板裁出带文字的角色卡；角色 PNG、角色名称、代码、坦奶和文案分别成层。

## 2. 设计系统（375 逻辑像素基准）

| 项目 | 规范 |
|---|---|
| 背景 | 暖白 `#FBFAF7`；纯白 `#FFFFFF`；答题正文面尽量无纹理 |
| 文字 | 主黑 `#242128`，辅助灰 `#68656E`；大标题深黑，正文避免纯紫 |
| 主色 | 紫 `#6A43D6`，用于主 CTA、单选和选中态；浅紫 `#F0E6FA` |
| 漫画点缀 | 淡薄荷 `#DCF6DF`、淡紫 `#EBD7FF`；珊瑚 `#F47B62` 只用于提醒或小面积重点 |
| 边界 | 细灰 `#DDDADD`；墨线约 `#242128`，用于少量外轮廓或重点气泡 |
| 栅格 | 安全区内左右边距 20px，页内竖向间距 8／12／16／24／32px；375 设计兼容 320—430 |
| 字体 | 中文正文用清晰无衬线系统字体；大标题可采用有漫画张力的字重或字形，但必须有字体授权及微信小程序回退；不得把生成图里的错字作为字库 |
| 字号 | 页主标题 28—32px，答题题干 20—22px，卡片标题 18px，正文 15—16px，辅助 ≥12px；行高正文约 1.5—1.6 |
| 点击区域 | ≥44px；答题选项一般 52—64px，长文案自然增高；按钮至少 48px |
| 组件形态 | 普通卡圆角 14—18px，漫画气泡可手绘边线但不歪斜正文；按钮可有笔刷底，交互外形仍需稳定可点 |
| 动效 | 轻微气泡弹出或线条划过 150—300ms；尊重减少动态设置；问卷无突发声光惊吓 |

**差异化原则：**首页和结果页靠人物＋几根高辨识墨线；答题页安静；找搭子用双卡片与连接线；找主题用真实剧目封面卡而非一列相同白框；队伍页是可商议任务板；预约是清晰凭证；商家工作台节制实用。别为所有页面套同一张“上方巨大标题＋下方几张白卡”。底部 Tab 为测一测／找搭子／找主题／我的，线性图标配文字；选中为淡紫笔刷底或墨线下划，安全区完整。

## 3. 页面完整规格

### 3.1 测一测首页

顶部品牌“入戏档案”，主文案“你是哪种入戏玩家？”与短副文案“先认识自己，再找一起入戏的人”。`bg-home.png` 的淡色走廊衬托正式角色资产：没有报告时可显示**已授权、明确为示例**的角色，或者空的角色预留位；有报告时显示本人的正式角色立绘，立绘与标题不得重叠。主按钮“开始测试”／“继续第 N 题”，辅助“看看角色图鉴”；基础 60 题、条件补问最多 100 题、可保存的短说明紧随按钮。不存在草稿则不能显示“继续上次”。显示旧版报告时标历史版本并提供重新测试，而非默默改写旧答案。

### 3.2 用户资料与外观设置

昵称、已有密室经验可用于展示和沟通；真实年龄／自述性别等业务资料按必要场景分步索取，可“不透露”。漫画男童／女童／可选中性是**独立外观选项**，不是推断真实属性。照片／个人资料／同意共享条件须单独授权，提供返回和稍后填写。年龄资格在具体主题预约环节以真实条件核对，不能因为小鬼形象判断成年人或未成年人。

### 3.3 基础问卷（核心页面）

完全按照方向预览的中屏：顶栏返回、标题“入戏问卷”、文字操作“保存退出”；真实的“基础 01/60”题位与“已完成 0/60”分开，细进度条按已完成题数量显示；题干在近白背景上可一眼读完；五级选择纵列，`无法判断`位置始终固定且视觉上有轻分隔。选中后浅紫背景＋紫色圆点，**不自动下一题**。底部安全区上方固定“上一题／下一题”；上一题首题禁用、下一题未选时禁用并提示。修改答案标未保存并显示保存状态；离线、失败与草稿恢复设计明确。题干和选项不改原文案、不改答案次序和计分语义。320px 仍能看清六行，不把 CTA 覆盖在“无法判断”上。

### 3.4 分支入口、补充问卷与答卷检查

基础阶段结束后以一张轻量漫画问号纸条说明“有些选择需要再确认”，区分影响坦奶判定的必要澄清与可选深化；显示当前完成数和可能增加的题量，不提前揭晓标签。补充分组显示局部进度；阶段结束才决定下一组。检查页按未答、未知、暂缓分支展示具体可补答入口；完成率满但资料不足时可查看部分结果，不能输出伪造的代码／胆量子类。

### 3.5 人格结果首屏与详情

结果首屏使用 `bg-result.png`，中部摆放**用户正式角色立绘**；顶部名称和代码，角色图区不能被额头上横排字遮挡。名称、`ADVC-K`、`微坦 T-M`分层明确，文字由运行时真实数据驱动。主文案简短可分享，下方三操作“找搭子／看主题／分享”。已知、临界、未知／待补答、仅想象作答、历史版本分别有显式状态，未知不伪装确定。角色动作按 K/R 和四种坦奶反应选用正式资源，无法确定胆量时用批准的中性立绘槽。

详情用五字母解释卡、六星图＋六行文字表、坦奶反应证据、剧情共鸣与是否容易落泪两个独立标签、“玩得舒服的条件”“需要提前商量的事”；详情页面背景以纯暖白为主。六星图 unknown 不连零点。优先给人能读懂的解释，不用“匹配成功率 98%”等没有验证的结论。剧情感性不自动判奶、哭泣不自动判喜欢高恐。

### 3.6 16 角色图鉴与详情

标题“16 个方向，都是入戏的一种”，图鉴每卡按真实主代码引用用户已有角色资源：不同的专属道具、姿态缩略图、名称、四字母代码、一句独特玩法倾向。提供 K/R 切换和四类坦奶**示例**反应，图鉴与个人实际结果有醒目标识差异。角色素材缺少某项时显示状态和统一兜底，不复制同一鬼图冒充 16 种人格。预览卡尽量形成错落的双列编辑式节奏；详情承载完整角色故事和换装演示。此页以 CSS 白底和淡色笔刷装饰实现，不额外拉满一张背景大图。

### 3.7 找搭子与真实双人报告

找搭子页用 `bg-teammate.png` 的上段画面：上部标题“找个合拍的搭子”，下面三个功能区——“类型参考”显示假设人格的搭配方向并明确非真人；“邀请好友”是明确主 CTA，未邀请时给有内容的空状态；“胆量搭配”给坦奶组合说明。真实双人页面在双方同意后展示两张真实角色卡、共同点、可能需商量的任务、未知信息和权限范围；双奶轻喜剧文案后跟实际低恐及陪同建议。不能展示“在线 999 人”等假社交数字；对方不同意时不能展示她／他的原题答案、私人拒绝原因或雷达详情。

### 3.8 队伍页

成员及邀请状态、队伍人数、计划日期与题材以可操作筹备板呈现。每人只显示授权的必要条件；待商量任务做成具体问题卡：“这段能否两人同行？”“谁愿意做最后一位？”明确拒绝不可被团队投票覆盖。队伍成员变化、角色分配变化、授权撤回或主题版本变化后显示适配需重算；不自动要求坦带奶或强迫奶做单人任务。

### 3.9 找主题与主题详情

找主题入口使用 `bg-theme.png` 作为顶部背景／空状态。真实数据接入前明确“正在接入门店与场次”；演示主题盖“演示剧目”标记且**不可预约**。真实列表用**商家实际海报**（须商家提供与许可）作为主题卡主体，展示题材、人数、时长、玩法强度和经核实的配置；平台背景图不能假装某店真实主题海报。详情按无剧透梗概、实际玩法、贴脸／追逐／突发声音／黑暗／单人任务必做或可选、路线角色、陪同与商家确认版本组织。商家缺项时标“待确认”，明确拒绝冲突时给换路线／换主题入口；“适合某人格”只是参考，不等于某玩家具备预约资格。

### 3.10 队伍 × 主题适配、路线／角色／场次

用人物条件列、任务列、支持安排列展示逐项核对，不堆积雷达曲线。状态必须区分“有明确冲突／待商家确认／可提交申请／数据已过期”。场次视图只展示真实库存与来源；人数、角色分配、同时发生任务和商家能否提供陪同需要核实。主题版本、时间或人数变化时重算并提示，支持回退调整。没有接入真实商家时给清楚的不可申请状态，不显示伪造场次。

### 3.11 预约申请、订单状态与商家工作台

预约确认页像清晰的入场凭证：门店、真实主题配置、日期、人数、金额／待确认、关键支持、条款；玩家逐项核对后按钮是“提交预约申请”。订单时间线区分申请已提交→商家审核→留位／报价→玩家确认→预约确认；付款、退款另标真实状态。过期／拒绝／改动需要用户再次确认。商家工作台独立，干净功能性界面，入口门店资料／主题版本／场次／待确认安排／预约／反馈。导入识别只能产生草稿，关键玩法证据与公开无剧透文案由商家确认。员工仅查看本店必要资料，无法浏览玩家原始问卷。

### 3.12 分享海报与我的

分享海报在漫笔背景和角色立绘上显示真实角色名、五字母代码、可选坦奶徽章、玩家选择的短句、可选雷达和两个剧情情绪标签；剧情标签默认关闭，真实年龄／自述性别／原始答案／具体拒绝项永不默认分享。预览确认后生成真实分享快照；无已发布入口不造假二维码。我的页面展示报告与版本、队伍、预约、换装、授权与删除；换装不重算人格，历史报告提示版本。

## 4. 全局页面状态与组件交接

组件需至少覆盖 `PageHeader / BottomTabs / PersonaArtworkSlot / ComicTitle / BrushLabel / ProgressRail / QuestionChoice / UnknownChoice / PrimaryButton / SecondaryButton / StatePill / EvidenceDrawer / TypeCard / InviteCard / MemberCard / ThemeCard / TaskSupportRow / BookingTimeline / SharePrivacyToggle / EmptyState`。每个可交互组件给默认、按下、选中、禁用、加载、错误、待确认；状态词配图标或说明，不靠颜色独自识别。所有重要页面交付正常、空、资料不足、网络错误、无权限、过期、冲突、成功，且每个状态有下一步。

资产与 UI 不绑定：所有背景都可关闭，关闭后页面仍完整可读；低性能机先加载 UI，再加载背景；背景失败时优雅降级为暖白纯色。考虑微信导航胶囊、状态栏、机型安全区、输入法遮挡以及长内容滚动。建议背景使用压缩适配产物，**本包 PNG 是母版，不要未经优化把 1—2 MB 原图四张全部打入初始包**：在实际项目中按路由异步加载、生成合适宽度 WebP 或受平台支持的格式并目测验证。不要缩放拉伸 941×1672 原画或把测试题目压在背景线稿上。

## 5. 交付顺序与验收

1. 先输出项目实际文件映射、设计变量、四张背景的接入计划、正式角色资源接入位。未获得角色文件时只完成 UI 插槽与可运行的兜底状态。
2. 先完成首页、基础问卷、结果首屏三个**与已确认预览方向一致**的页面；提供 375px 和 320px 实际运行截图以核对层级。文案须按业务数据和原题纠正，不照搬设计图里可能不准确的 AI 排字。
3. 完成图鉴、找搭子、队伍、主题、适配、预订、我的及商家工作台；每页至少一张正常状态和一张关键异常状态的截图。给出样式变量、组件状态及背景裁切标注。
4. 验收硬条件：正式角色不被重画；背景与角色可以独立替换；四张图只出现在指定位置；问卷在 320px 可读且答题不自动跳；坦奶互斥且允许未知；六星图和剧情标签语义准确；邀请需授权；演示主题不可预约；拒绝和商家未知不会被“高匹配”覆盖；申请不显示为已确认；换装不改人格。
5. 提供变更文件列表、开发环境验证方法、页面截图与尚未接入的真实商家／角色素材缺口。不要把设计预览当成业务实现完成。

## 6. 本包与源素材的关系

`reference/approved-direction-preview.png` 是审美与布局方向；其中角色是用于验证排版的示意性图像，不用于项目最终上线。实际页面应消费用户另行准备的人格角色图，并按代码、K/R、坦奶子类、外观表现和表情帧选择相应资源。新增背景图片是为了提供**空间感与角色衬底**，不承担人格与题材真实性。若角色图本身已有极强笔触，优先降低背景不透明度，不为“沉浸”损害识别度。
