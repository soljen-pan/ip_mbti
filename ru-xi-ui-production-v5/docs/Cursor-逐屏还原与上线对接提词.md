### 1.2 为什么不把整屏裁成一张图

已确认效果图中的页面标题、号码、问题、答案、按钮、进度、导航、坦奶徽章、预约状态都必须由真实文字与组件生成。用整屏图替代会使 56+44 题、无障碍字号、系统胶囊安全区、登录切换及错误提示失效。背景只裁档案夹、淡色纸面、角色透明前景、品牌字样，**这些才能在更换角色和状态时持续复用**。

未登录及测试中首页的图层从后到前固定为：`#F8F8F8` 页面 → 浅色档案夹 → 可替换透明双人图 → 可选轻量索引签/状态印章 → 真实的“未解锁档案”或“进行中”文字、题量/进度、按钮。顶部文字、底部 TabBar 均不位于背景图内部。人物不覆盖任务入口和可点击控件。

`375px` 逻辑宽基准，原型的主视觉可见区域约 `335 × 306px`，双人插画居中 `contain`，左右留至少 `8px` 安全边距，脚与道具均入画。320px 窄屏按宽等比缩放英雄区高度；430px 宽屏增加外部留白，不能拉长人物。小程序图片资源保持 2x 清晰，压缩与分包以实际机型和包体核验为准。角色为透明层时可独立换装；背景采用固定比例或九宫格切片，不在高宽不同比例下任意硬拉伸纸张纹理。

`folder-cream.png` 是为复用重绘的无字底图；`folder-blue.svg` 是可编辑形状重建。双人透明图是对已确认构图的二次创作，IP 标准字来自你提供的品牌板。原图没有交付可编辑分层源稿，故结构能高还原，纹理细节无法被称为原图逐像素切出；接入最终 IP 母版素材时应替换对应层，无须重写页面。

### 1.3 微信工程中如何放置

原生小程序：背景放 `assets/ui/backgrounds/`，人物放 `assets/ui/characters/`，导航图标放 `assets/ui/icons/`；Taro/uni-app 按项目约定映射。使用独立组件 `FolderStage` 接受 `{variant: locked|progress, illustration, status, progress}`，动态内容由 `view/text/button/image` 分别承载。角色图采用 `mode="aspectFit"`；图标使用当前技术栈已验证能在微信端渲染的本地格式。不能把浏览器 CSS、SVG、字体加载写法直接复制进微信工程而不做真机兼容测试。

不自动引入 17MB 的原型审阅字体到小程序；原型本地字体只为了稳定生成截图。正式端优先系统中文字体，按截图中字号、字重、行高逐页比较。

## 2. 样式、组件与交互统一规范

| 对象 | 基准样式与行为 |
|---|---|
| 页背景 | `#F8F8F8`；纸档案独立浅奶油色；问卷内容区纯浅色，禁止满屏插画 |
| 标题 | 暗黑 `#111111`，28px/1.2 粗体；结果主名约23px；问卷题干21px/1.42 |
| 主按钮 | `#693E7D` 纯色填充、白字、48px 最小高、8px 圆角；无黑描边、投影与位移；按下 120—160ms 只切换深紫 `#59316E` |
| 次按钮 | 骨白或浅紫底、浅灰紫 1px 细边或无边框，48px 最小高、8px 圆角；禁用用 `#E7E3E8` 底和 `#817A82` 字，并说明原因 |
| 按钮状态 | 默认与选中都不加阴影；按下仅改背景色，禁止下移、缩放或出现浮雕边；加载时保留原宽度并显示旋转指示及“处理中”；焦点有 2px 紫色外轮廓 |
| 魅紫 | `#7B5A8F` 用于选中图标、进度、徽章、重要链接与印章 |
| 粉紫 | `#D964E3` 点缀发饰/小图标/小面积光点；不能做浅底说明文字（对比不足） |
| 鬼肤蓝灰 | `#DCE5F3` 用于进行中档案底、人物区浅色背景；不要给“信息未知”默认为安全含义 |
| 行与卡 | 普通列表行约52—56px；主视觉/场次/邀请使用少量纸卡，边框1px；不以卡墙塞满 |
| 单选题 | 至少53px、行间8—10px；选中浅紫底＋紫色边＋圆点；unknown 独立末项但同等可读 |
| 导航 | 根页四 Tab“测一测/找搭子/找主题/我的”；详情页有返回和首页，适配胶囊安全区 |
| 底栏 | 安全区之上固定操作，正文容器需要等高补白；输入框/键盘弹出后按钮不挡内容 |
| 状态 | 所有状态文字＋必要图标一起表达：待核实、已确认、冲突、空、断网、加载、过期 |

色值已验算：`#7B5A8F` 在骨白上文本对比约5.34:1；深紫按钮白字约8.12:1；粉紫在骨白上约2.87:1，所以粉紫不能单独承担文字或表单状态。准确样式值在 `docs/design-tokens.json`；原型实现可见 `preview/style.css`。

动效只用于按下反馈、分区切换、弹层展开；页面没有音效、自动惊吓、角色持续摇动。用户减少动效时退化为静态，不能通过动效才能识别选中状态。

## 4. 每条流程如何工作

### 4.1 登录与未登录

**初始访客：** 能看首页、图鉴、玩法、公开主题与类型参考，能开始本地答题。首页显示“未解锁档案”男孩女孩双人插画。个人中心无昵称、头像、测试结果或虚构数据。点击邀请队友、建队、保存需要账户的业务、预约或账户资料时，记录 `pendingDestination` 与输入草稿，打开登录页，并保留取消路径。

**登录并且尚未答题：** 显示账号资料行和“开始测试”；角色区可展示双人示意，不会提前给出人格代码或坦奶身份。

**登录＋测试进行中：** 首页显示“进行中”男孩女孩双人插画、实际基础已处理数/56、真实本地或云端保存来源和“继续测试”。`unknown` 表示已处理但缺判断，未答不计入已处理数；隐藏总题数只显示已触发本段数，不能写 61/56、100/56。

**登录＋已完成：** 显示本人已生成的报告摘要、正式角色与独立胆量标签；再次测试为独立新测评，不无提示覆盖历史报告。

**访客已在本机完成测试时：** 在同设备先显示本地报告/继续登录保存；如业务允许需要保护敏感分享，发起真实邀请/队伍/预约仍走登录。登录合并本地草稿与该账号云端草稿前，明确列两个版本的进度与时间，让用户选择保留哪个；禁止悄悄覆盖。注销后清除该账号本机私有缓存；访客草稿不与别人的账号串档。

**微信身份和资料：** 用户主动进入登录页，登录成功仅说明小程序账户身份建立。头像和昵称单独由用户选择/填写，头像临时路径经过实际上传与服务端保存后才显示“已保存”。用户取消资料填写可在允许的页面继续；涉及对外展示的场景用已确认昵称或用户自行填入的替代称呼。不得声称登录自动取得微信头像和昵称。正式适配按实施当天微信官方文档、基础库、隐私规则与真机回归核对。

**失败/取消：** 登录失败回到原页并保留输入，提供重试。未授权分享不发邀请；会话过期提交预约前重新核验；登录后的回跳不能自动重放支付、邀请发送、申请提交等有外部副作用的动作。

### 4.2 答题与报告

题库从 v2.0 加载 B001—B056 与 H001—H044，本包 `preview/question-bank-extracted.json` 从上传的规格文档提取100个题号和题干，供 UI 对文案与换行；**不是评分、选项、触发完整配置**。正式上架必须使用已发布的题库配置及其 option_set、方向、分支策略和版本。

基础题的 L5 是五个固定选项加“无法判断”。这两个状态独立于数值3“居中/看情况”；B051—B055 的 `ACCEPT` 与 B056 的 `ONE` 不能套普通五档。H005/H008 是父子条件：H005 确认独立/陪同后，H008 只能显示对应父类内部的二选一加 unknown；父类未知不能任意展示坦奶四标签。原型只演示 C 线前 8 题的界面，**不可作为完整44题的触发引擎**。

单选不自动跳题，用户点“下一题”才切换。保存退出保留当前位置/答案/分支队列/版本；本地持久与服务端同步分别显示真实状态。退回修改触发补题变更时，失效分支与派生报告按业务规则重算。结果中的坦或奶只确定其一，正式身份只巨坦/微坦/尖叫奶/哑巴奶；信息不足显示待补答。五字母与 K/R、坦奶、六星图、故事感性/落泪字段均分开；**附件无完整落泪字段协议时不要伪造该标签**。

正式结果页的“档案解读/六星图/图鉴搭配”用三个可点击分区。固定雷达轴序是入戏投入、互动意愿、探索欲望、刺激偏好、动能偏好、协作意愿；缺失轴不补0，提供文字值或“待补充”。图鉴候选、已获两人同意的真实匹配、多人组队、主题适配、预约资格，分别呈现，不用共同的“匹配成功百分比”覆盖明确拒绝。

### 4.3 搭子、主题和预约

找搭子页的“坦＋奶”仅提示有互补可能；陪同依赖本人、队友、商家、时间地点和容量。双奶可以温和显示“门口礼让三百回合：您先，您先”，随后提供低恐与陪同选择。没有真实熟人授权时不展示假在线人和虚构邀请数。

主题页只展示已审核或明确标注演示的数据，区分 Theme/Variant/Role/Route/Session；库存未知不说“安全”“无贴脸”“有空位”，恐怖元素未知要提示核实。主题的类型方向建议与玩家本人具体适配分开。购买路径先硬边界、后软排序；无有效配置时只能“待确认/有冲突”，不能靠90分蒙混过关。

提交预约：成员对同一个安排修订、具体场次、价格/条款确认；商家核实；得到报价/留位；成员确认；服务端库存事务确认，之后才显示“预约已确认”。实际页面要能区分 `draft → submitted → merchant_review → offered → accepted → confirmed` 和取消/过期/拒绝。支付另有状态，未接支付不能显示“已支付”。刷新、超时、双击、过期、成员修改、商家改变路线需回服务端查询最新状态，并使旧确认失效。

### 4.4 商家工作台

有门店员工权限才出现入口；业务数据在服务端再次鉴权。主题编辑按故事、玩法、路线角色、陪同、资格、证据逐步展示，AI 提取为草稿，员工核实后发布版本。商家仅见必要安排，不见原始题库与私人拒绝原因。预订请求以“这个任务能否允许一人陪同”这样的具体问题呈现。

## 5. 交互状态表（Cursor 按此接实际 API）

| 用户动作 | 未登录 | 已登录但没有报告 | 已登录有报告 | 外部服务失败 |
|---|---|---|---|---|
| 测一测 Tab | 开始或继续本机草稿 | 开始/继续云端校验后的草稿 | 看档案/独立重测 | 留本机草稿并写“等待同步” |
| 找搭子 Tab | 类型方向可读；邀请需登录 | 可建队，组队建议注明资料不足 | 类型方向、好友邀请、真实协议 | 不生成假邀请成功 |
| 找主题 Tab | 浏览已公开主题 | 浏览，可完善本场偏好 | 适配前再收集本场条件 | 商家资料未知时显示待核实 |
| 我的 Tab | 明确登录入口及可读内容 | 账号资料＋测试状态 | 报告/队伍/预约/设置 | 不把请求失败渲染为“还没有报告” |
| 结果 → 分享 | 本地预览；正式分享先完成必要身份或按产品授权 | 数据不足说明 | 预览选择公开字段与撤销 | 小程序码生成失败给重试，不画假码 |
| 主题 → 预约 | 登录并返回主题场次页 | 本场条件不足不能提交 | 条件和库存确认后可申请 | 超时先查幂等结果，不盲目重复提交 |

每个按钮要有真实作用或准确禁用提示。加载、失败、空、被撤销、无权限、未开放、保存中、仅本地、已同步、已过期、留位到期、商家待答复用独立样式与文案。无真实商家时，生产环境的入口应明确不可提交，不能靠原型模拟按钮产生成功消息。

## 6. 逐屏测量与误差约束

基准视口是375逻辑px宽、约812高；系统导航与胶囊用设备实际安全区。`screenshots/*.png` 是375×812布局经2倍浏览器分辨率输出；对比实际开发者工具截图时先等比例缩到同一375宽，然后半透明叠图。

参考区域（从屏幕可视顶部起，状态栏实际高度由系统决定）：顶部状态约0—31px，导航约31—83px，正文从约83px起；左右常规14—16px。首页标题段约90—210px，首页档案舞台约225—531px，主按钮约541—589px，底部四 Tab 约742—812px。答题页进度在导航下约84—180px，题干约207—296px，选项约315—685px，底部操作区约734—812px。上述为审阅基准而非业务数据；当题干换行增加、系统字体放大、键盘弹出时允许向下流动。

校验方法：对首页访客/草稿、答题、结果三个核心屏，状态一致时标题起点、人物可见框、主按钮、底栏的可见边缘差距目标≤8逻辑px；非核心区块差距≤16px。不会为了凑像素覆盖系统胶囊或截断无障碍字号；优先保证完整文字、可点击面积≥44px和滚动通达。

**注意两套效果的关系：** 用户最先批准了纸档案结构与男孩女孩双人构图，之后交付新 IP 色板。现有 `approved-design.png` 中的橙色只是历史配色，验收请看本包最新运行截图与 tokens；不得做一套橙色首页、一套紫色详情。人物衣物里的紫色来自原角色稿，与新 IP 一致。
